Contextual execution and derived forms: working coverage
========================================================

This is the acceptance ledger for the contextual-derived-forms goal. It does
not redefine completion around the first checked modules. Source models and
runtime implementations remain separate evidence columns.

Source observations
-------------------
PeTTa's UnifyingSpec gives independent per-rule transitions and a checked
executable runner. A packet contains its value and branch substitution; a
configuration additionally retains the store, frames, input, output and
freshness counter. The source registry classifies written calls, while live
equations determine their bodies. Its return-value conventions and supported
control forms have versioned limits; native transform and once are not simply
new constructors of that source relation.

HE's Spec/Eval supplies independent entry, invocation, completion and minimal
instruction judgments. Raw minimal chain execution extends its live scope and
retains a caller origin and a binding frame. That read-only profile is distinct
from the state-writing publication model. Holding Atom syntax, completing a
function result, and requesting another evaluation are separate judgments.
