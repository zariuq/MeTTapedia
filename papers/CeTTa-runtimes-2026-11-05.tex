\section{Runtime Snapshot: 5 November 2026}
\label{app:runtimes-20261105}

This appendix measures the Linux preview's working source before its next
commit.  It is a dated local snapshot, not a claim that the historical tables
elsewhere describe the current executable.  The reproducibility record is
\code{benchmarks/snapshots/2026-11-05/} in the CeTTa repository: individual
trials, source and oracle hashes, the selected workload manifest, corpus
fixture policy, and build/environment metadata.  The problems are generated
by the tracked \code{benchmarks/mam\_families/app\_panel.py},
\code{join\_panel.py} and \code{path\_panel.py}; the shared runner is
\code{run.py}.  Expected answers are computed independently in Python.
Native MM2 fixtures also live under \code{tests/support/mork\_mm2/}; the
wider \code{benchmarks/mm2\_corpus/manifest.tsv} additionally names external
MORK resources and a separately versioned fork, so that wider corpus is not
entirely self-contained.

\subsection{Identity and measurement conditions}

The machine is an AMD Ryzen 7 9800X3D, with eight cores and sixteen logical
CPUs, running Linux x86\_64.  It is a shared workstation, not an isolated
benchmark host.  Process startup, library loading and normal output are
included.  The paired panel uses one logical CPU and three alternating trials
for every applicable engine/case pair; reported times are medians.  Its
five-second per-invocation cap was not reached.  Peak RSS is the largest
observed process peak over those trials, recorded separately in the TSV data.
Small millisecond differences are startup-dominated observations, not
steady-state kernel throughput.

The CeTTa executable reports \code{1.5.0-dev (main)}, with SHA-256 prefix
\code{5b05f6158ea3ce8f}; its source is based on commit \code{2ca1c923b93d}
plus the pending preview repairs.  Full digests are in the metadata.
This is the bridge-enabled \code{BUILD=main} CLI, linked with GMP,
SWI-Prolog and CPython 3.13.  Its timings do not measure the Prolog-free
Python-wheel runtime.

The SWI-PeTTa checkout is based on \code{b74af1bc26af}, with local edits to
its launcher, parser, reader and translator; its tracked diff digest and
individual example hashes are recorded.  This screen is therefore against
that working PeTTa tree, not a new conformance claim against an unmodified
release oracle.

\textbf{MORK provenance limitation.}  The measured artifact is the available
MORK release executable, with SHA-256 prefix
\code{13bd3d0b7a913b73}.
The adjacent source checkout is \code{ed57c6716d8c}, but the executable's
association with that source revision is unverified.  An attempted
\code{cargo build -{}-release -{}-locked -{}-offline -p mork} refused a
lock-file update.  No lock file was changed.  The numbers below compare these
identified local executables; they do not establish performance against a
fresh build of current upstream MORK.

17 selected cases, three trials per engine, with two cases applicable only
to CeTTa-PeTTa and SWI-PeTTa.  A dash means the generator supplies no program

explicit programs solving the same task, sometimes with different execution
plans or answer encodings.  It does not assert an identical algorithm or a

\subsection{Complete tracked top-level PeTTa example screen}

The population is all 164 tracked \code{examples/*.metta} files directly
inside the PeTTa example directory; nested directories are not included.
Each engine has one timed invocation per case and a two-second cap.  This
is a bounded coverage/timing screen, not a repeated latency study.  The
existing corpus fixture policy supplies scripted input and isolated I/O;
explicitly mapped cases use corrected-source or library fixtures.  The
snapshot records the fixture kind and actual fixture-source digest as well
as the original example digest.

There are 156 matching normalized observations, five capped SWI-PeTTa
invocations, and three exit differences.  The exit differences are
\nolinkurl{python.metta}, \nolinkurl{python_import.metta} and
\nolinkurl{test_unify_eval_branches.metta}: the first two expose provider
value/string distinctions, and the last fails to load \code{lib/lib\_he} on
CeTTa.  They remain visible rather than contributing speedup ratios.  Nor is
an agreement necessarily a successful application: matching exit status and
normalized output can include a shared deliberate failure.  The TSV records
both exit codes.  In the table, ``ok'' means matching observations, ``cap''
means the SWI invocation was incomplete, and ``exit'' means differing exit
status.  Times are milliseconds; $>2000$ is the cap, not a completed runtime.

\paragraph{Reproduction boundary.}  The snapshot's \code{reproduce.txt}
lists the generator and runner commands and selected cases.  Raw process logs
and stores were retained with the measurement run; the repository carries the
small machine-readable receipts and independent workload definitions.
This snapshot does not requalify portable wheels, physical AArch64, GMP
allocation-failure recovery, Prime or the paper's older heavy genomic and
proof-search benchmarks.
